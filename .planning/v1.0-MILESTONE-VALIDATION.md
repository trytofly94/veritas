# Milestone 1.0 — Validation Report (Iteration 3/3)

## Summary

The milestone ships a near-complete forensic archive pipeline. The cryptographic core (hash, TSA, bundle, verify.sh), all HTTP API flows (upload auth gates, download ZIP), the archive list, and the detail page's metadata rendering are all working correctly — including the iter-1 field-name fixes (Bezeichnung and Server-Zeitstempel now populated). A new blocker was found in this live E2E run that was invisible to static analysis: the archive-detail page's Alpine.js components (`verifyIntegrity`, `copyState`) fail to initialize because `archive-detail.js` is loaded AFTER `alpine.min.js` with `defer` scripts, causing `alpine:init` to fire before the `Alpine.data()` registrations run. The "Integrität prüfen" button renders with empty text and throws `run is not defined` when clicked. The underlying `/api/archive/:id/verify` API endpoint returns `{ok:true}` correctly, but no user can trigger or see the result through the browser UI. This directly violates BROWSE-02 SC-2: "being able to confirm its integrity". This is iteration 3 of 3 (max_iterations reached) — human decision on ship/fix required.

## Project Type Detection

Detected: **mixed** (UI + API)
Signals: Hono HTTP server in `src/server.ts`, server-rendered HTML views in `src/views/`, vendored Alpine.js in `src/static/`, login/upload/archive-list/archive-detail HTML pages, `/api/*` JSON routes for upload+verify+download.

## Code Review Findings

### Blockers (1)

**B-3. Alpine.js initialization race on archive-detail page — "Integrität prüfen" button is completely non-functional.**

Location: `src/views/archive-detail.ts:104-105`
```
<script defer src="/static/alpine.min.js"></script>
<script defer src="/static/archive-detail.js"></script>
```

Evidence from live browser console (11 ReferenceErrors at page load time):
- `ReferenceError: verifyIntegrity is not defined` — x-data="verifyIntegrity('01KRWS8V5TN9QCV1W40RAPSBY3')" on the verify section fails to initialize Alpine component
- `ReferenceError: copyState is not defined` — x-data="copyState()" on the copy section fails to initialize Alpine component
- `ReferenceError: state is not defined` (x4) — all x-text and x-show bindings that reference `state` throw because the component was never initialized
- `ReferenceError: run is not defined` (x2) — @click="run()" on the verify button throws when clicked
- `ReferenceError: copyValue is not defined` (x2) — @click="copyValue(...)" on copy buttons throws when clicked

Root cause: `defer` scripts execute after DOM is ready, in document order. Alpine 3's `alpine:init` event fires during `alpine.min.js` initialization. By the time `archive-detail.js` executes and calls `document.addEventListener('alpine:init', ...)`, the event has already fired — so `Alpine.data('verifyIntegrity', ...)` and `Alpine.data('copyState', ...)` are never registered. Alpine then cannot resolve the x-data component names.

The upload page (`src/views/upload.ts:27-29`) avoids this exact issue with a comment: "upload.js must load before alpine so window.uploadForm exists when Alpine evaluates x-data" — and loads `upload.js` BEFORE `alpine.min.js`. The archive-detail page does not follow this pattern.

User-visible impact: The "Integrität prüfen" button renders as an invisible unlabeled button (its x-text="..." renders empty string). Clicking it throws `run is not defined` in the console and produces no visible response. The verify result card never appears. The API endpoint works correctly (`{ok:true}`) but there is no functional UI to access it.

BROWSE-02 SC-2 requires "being able to confirm its integrity" — this is unmet via the browser UI.

Fix: In `src/views/archive-detail.ts`, swap the script order to load `archive-detail.js` BEFORE `alpine.min.js`:
```html
<script defer src="/static/archive-detail.js"></script>
<script defer src="/static/alpine.min.js"></script>
```

### Concerns (3)

**C-1. Web upload confirmation card renders TSA-Anbieter and Zeitstempel as empty.**
- Location: `src/routes/upload.ts:258` returns `{id, bundle_path}` — no `tsa_provider`, no `tsa_attested_at`
- Evidence from browser: success card shows `{"Archiv-ID":"01KRWSDA13TXWC2A0631AJNA1R", "TSA-Anbieter":"(empty)", "Zeitstempel":"(empty)", "Status":"✓ Verifiziert"}`
- Status: CONCERN (carried from iter-1, unfixed). Not a BLOCKER because the user sees the archive ID and hardcoded "✓ Verifiziert" badge.
- Fix hint: extend 201 response: `c.json({ id, bundle_path: bundlePath, tsa_provider: tsa.provider, tsa_attested_at: tsa.attestedAt }, 201)`

**C-2. Session cookie unconditionally sets `Secure`; breaks login over plain-HTTP LAN.**
- Location: `src/routes/login.ts:68,79`
- Impact: `http://192.168.178.30:3000` (documented Unraid smoke-test URL) will silently reject the session cookie. Production deployment via Cloudflare Tunnel (HTTPS) is unaffected.
- Fix hint: gate `Secure` on `COOKIE_SECURE` env var (default true).

**C-3. Archive list DB-failure branch returns JSON envelope on an HTML page.**
- Location: `src/routes/archive.ts:73-79`
- Impact: a logged-in user whose SQLite throws sees raw JSON instead of an error page.
- Fix hint: render HTML error page instead.

## Recommendation

**ESCALATE** — iteration 3 of 3 reached with 1 blocker found in live E2E.

B-3 is a trivial 2-line fix (swap `<script>` order in `src/views/archive-detail.ts:104-105`). However, per max_iterations protocol, human decision is required:

Option A: **Quick fix and ship** — swap the two `<script>` lines in archive-detail.ts, re-run unit tests (`npm test`), confirm Alpine components initialize. This is the recommended path given the fix is mechanical and low-risk.

Option B: **Ship with known gap** — the API endpoint `/api/archive/:id/verify` works; the UI is cosmetically broken. Users can still verify integrity via curl. Not acceptable for a milestone that explicitly promises a browser UI verify flow (BROWSE-02 SC-2).

Fix change: `src/views/archive-detail.ts` line 104-105 — put `archive-detail.js` before `alpine.min.js`, exactly mirroring `src/views/upload.ts:27-29` which has an explanatory comment on this ordering requirement.
