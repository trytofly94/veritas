<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| process startup ↔ env | required env vars must exist before port bind (D-06) |
| signed cookie ↔ untrusted browser | cookie body is base64url-decoded user input; HMAC binds it |
| VERIFY.md template ↔ user-controlled label | filename in template originates from user input |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | sessionCookie.verify | mitigate | timingSafeEqual on MAC + length pre-check; reject expired; D-02 |
| T-02-02 | Tampering | sessionCookie.verify | mitigate | HMAC-SHA256 binds body↔mac with SESSION_SECRET (≥32 bytes enforced in loadConfig); D-02/D-06 |
| T-02-03 | Information Disclosure | errorEnvelope.onError | mitigate | response message is "Unbekannter Fehler."; stack/details only via console.error server-side; D-23 |
| T-02-04 | Tampering | verifyTemplate.renderVerifyMd | accept | template is a static asset; user-controlled values (filename, label via metadata) are substituted as plain text into Markdown; no shell/HTML execution context; risk: Markdown rendering elsewhere could honor links — accepted because VERIFY.md is opened locally as plain text or by a trusted Markdown viewer |
| T-02-05 | Denial of Service | loadConfig | mitigate | fail-fast process.exit on missing env eliminates "running but broken" state; D-06 |
</threat_model>
