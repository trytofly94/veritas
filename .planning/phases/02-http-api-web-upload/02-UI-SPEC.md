# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2 frontend surfaces.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored HTML + Alpine.js |
| Icon library | none — text/emoji indicators only (trust signals use text badges) |
| Font | system-ui, -apple-system, "Segoe UI", sans-serif (system stack, no external load) |

**Rationale (from CONTEXT.md D-07, CLAUDE.md):** Alpine.js is vendored as a static asset (no CDN). No build step. No Tailwind. CSS is hand-authored in a single `<style>` block or a static `assets/style.css` file served by Hono. All HTML is rendered server-side by Hono template strings; Alpine.js handles reactivity on the client.

## Color

Palette is neutral-dominant with a single green accent. No brand color. The UI communicates trustworthiness through restraint, not color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f9fa` | Page background, form surface |
| Secondary (30%) | `#ffffff` | Card/panel backgrounds (upload card, confirmation card, login card) |
| Accent (10%) | `#16a34a` (green-600) | TSA verified badge, progress bar fill, success state border, "Download ZIP" button |
| Destructive | `#dc2626` (red-600) | Inline form errors, API error message text, 413 size-limit error banner |
| Border / muted | `#e2e8f0` | Card borders, input borders, dividers |
| Text primary | `#0f172a` | All body and heading text |
| Text muted | `#64748b` | Help text, secondary labels, timestamps |

Accent (`#16a34a`) is reserved for exactly: TSA-verified status badge, progress bar, confirmation card left border accent stripe, "Archiv-Bundle herunterladen" button.

Destructive (`#dc2626`) is reserved for exactly: inline field validation errors, upload error banner (file too large, server error, auth error), login wrong-password message.

**Design rationale:** Green signals cryptographic success (TSA verified). This is a courtroom-grade evidence tool; the palette should read like a bank statement, not a consumer app.

## Interaction Contract

### XHR Upload Flow (D-08)

1. User selects file (drag-drop or picker) → file name + size appears in drag zone; submit button becomes enabled
2. User fills optional label → no validation on typing
3. User clicks "Jetzt archivieren" → XHR POST to `/api/upload` (multipart)
   - Button disabled immediately (prevent double-submit)
   - Progress bar appears (0→100% driven by `XMLHttpRequest.upload.onprogress`)
4. On `200` response → parse JSON, render Confirmation Panel (form hidden, panel shown via Alpine `x-show`)
5. On error response → parse JSON `code` field, display appropriate error banner, re-enable submit button, form remains visible for retry

### Login Flow (D-04)

1. `GET /login` returns the login page HTML
2. User submits form (`POST /login`, `application/x-www-form-urlencoded`, field: `password`)
3. Server validates:
   - Success → sets HMAC session cookie, redirects to `/` (or `?next=` if present and safe)
   - Failure → re-renders login page with `?error=1` query param; Alpine reads param and shows inline error message (OR server renders the error inline — planner picks; both are acceptable)
4. No JavaScript required for the login flow — it works with pure HTML form POST + server redirect

### Copy-to-Clipboard (Archive ID)

- Clicking "Kopieren" calls `navigator.clipboard.writeText(archiveId)`
- Button label changes to "Kopiert!" for 2 seconds, then reverts
- Implemented with Alpine.js `x-data` reactive state on the confirmation panel

## Accessibility Baseline

- All form inputs have associated `<label>` elements (explicit `for` / `id` binding)
- Error messages are associated with inputs via `aria-describedby`
- Progress bar uses `role="progressbar"` with `aria-valuenow` / `aria-valuemax`
- Drag-drop zone has `role="button"` and `tabindex="0"` with keyboard Enter/Space activation
- Color is never the sole carrier of information (TSA verified badge has text "Verifiziert" alongside green color)
- Focus outline: `outline: 2px solid #16a34a; outline-offset: 2px` on all interactive elements

## Implementation Notes for Executor

- Alpine.js version to vendor: `3.x` latest stable at time of implementation. Download from `https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js` and place in `src/static/alpine.min.js` (or equivalent static assets path chosen by planner)
- CSS: hand-authored in `src/static/style.css`, served at `/static/style.css` by Hono static middleware
- HTML: rendered by a `src/views/` module (template strings or a minimal HTML builder — planner picks pattern)
- The API key is injected into the upload page HTML at render time (D-11): `const apiKey = Bun.env.API_KEY` — rendered into the `x-data` Alpine component as a JS literal. The planner must ensure this is not leaked to unauthenticated `GET /` if the access model changes
- The ULID displayed in the confirmation panel must be truncated for display only if it exceeds visible space — full value is always what goes into the clipboard
