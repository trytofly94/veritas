<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| client ↔ /api/download/:id | auth via X-API-Key OR session cookie; either is sufficient (D-12) |
| route ↔ filesystem | absolute bundle_dir path stored in DB; route reads files under that path |
| route ↔ Markdown render | meta substituted into VERIFY.md as plain text inside an inert template |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-26 | Spoofing | authOrApiKey on /api/download | mitigate | timing-safe X-API-Key compare OR HMAC-verified cookie; either is enough (D-12, D-01, D-02) |
| T-02-27 | Information Disclosure | bundle_dir in error message | mitigate | route's INTERNAL_ERROR envelope is generic German message; the path is only console.error'd server-side (D-23) |
| T-02-28 | Tampering | path traversal via id param | mitigate | id is regex-validated to ULID alphabet `[0-9A-HJKMNP-TV-Z]{26}` BEFORE DB lookup; even if the regex were bypassed, bundle_dir is read from the DB row (server-controlled), never from the URL param. |
| T-02-29 | Information Disclosure | ZIP cached by intermediary | mitigate | `Cache-Control: no-store` set unconditionally per CONTEXT &lt;specifics&gt; — evidentiary bundles must not be cached. |
| T-02-30 | Denial of Service | very large bundle stream | accept | Bundle sizes are bounded by the 100 MB upload cap × small const overhead; max stream size ~100 MB. No per-IP rate limiting in v1 (deferred). |
| T-02-31 | Repudiation | which TSA signed THIS bundle | mitigate | VERIFY.md TSA-Vertrauensquelle section names `{{tsa_provider}}` from metadata.json — locked in D-16 + Plan 01's template. |
| T-02-32 | Tampering | ZIP entries differ from on-disk bundle | mitigate | archiver streams each file directly from row.bundle_dir; integrity is guaranteed by the consumer's later sha256 + openssl ts -verify of the unzipped contents. The route does not re-hash or re-sign anything. |
</threat_model>
