## Surfaces in This Phase

Three distinct page surfaces:

| Surface | Route | Auth required |
|---------|-------|---------------|
| Archive list (entry index) | `GET /archive` | Session cookie (redirects to `/login` if absent) |
| Archive detail (single entry) | `GET /archive/:id` | Session cookie (redirects to `/login` if absent) |
| Login page | `GET /login` | None — reused from Phase 2, no changes needed |

Auth entry/exit for Phase 3 pages:
- Any unauthenticated request to `/archive` or `/archive/:id` → server-side redirect to `/login?next={url}`
- After successful login → server redirects to `?next=` value if present and is a safe relative path (`/archive` or `/archive/:id`); otherwise `/`
- Logout: existing `POST /logout` from Phase 2 ends session and redirects to `/login`

### 1. Archive List Page (`/archive`)

Page-level layout: wider than Phase 2 upload form. Container max-width `800px`, centered.

**Primary focal point:** Filename column in the table — 16px text primary, leftmost column, highest contrast against the muted metadata columns to its right. The eye anchors here first; all other columns (date, type, status) are 14px text muted and subordinate.

```
┌──────────────────────────────────────────────────────────────┐
│  Archiv                              [+ Neue Datei]           │  ← 20px/600 heading + secondary btn
├──────────────────────────────────────────────────────────────┤
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Dateiname    Datum            Typ      Status         │  │  ← Table header, 14px muted
│  │  ──────────────────────────────────────────────────    │  │
│  │  contract.pdf  2026-05-17 14:32  PDF    [DFN]          │  │  ← Row, 14-16px, clickable
│  │  photo.jpg     2026-05-16 09:11  JPEG   [FreeTSA]      │  │
│  │  note.txt      2026-05-15 22:05  TXT    [Lokal]        │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  (empty state when no entries)                               │
└──────────────────────────────────────────────────────────────┘
```

Table columns (in order):
1. **Dateiname** — original filename, 16px text primary, truncated with `text-overflow: ellipsis` at 200px max-width
2. **Datum** — `server_timestamp` formatted as `YYYY-MM-DD HH:mm` (UTC), 14px text muted
3. **Typ** — uppercase MIME subtype (e.g. "PDF", "JPEG", "TXT", "ZIP", "—" for unknown), 14px text muted
4. **Status** — TSA status badge (see badge spec below)

Row interaction:
- Entire row is a clickable link (`<a>` wrapping the `<tr>`, or `onclick` navigation) to `/archive/:id`
- Hover state: row background `#f1f5f9` (slate-100)
- No checkbox selection, no bulk actions in v1 (BROWSE-03 is v2)
- Sort order: chronological descending (newest first) — server-rendered, no client-side sort in v1

Empty state (when no entries exist):
```
┌────────────────────────────────────────────────┐
│  Noch keine Dateien archiviert.                 │  ← 16px text muted, centered
│  Lade eine Datei hoch, um zu beginnen.          │
```

### 4. Integrity Verification Component (in Detail Page)

Triggered by "Integrität jetzt prüfen" button. Implemented with Alpine.js `x-data`.

States:

**Idle (default):**
```
[Integrität jetzt prüfen]   ← .btn--secondary, 44px
```

**Checking:**
```
[Integrität wird geprüft …]   ← button disabled, label changed
```

**Success:**
```
[Integrität jetzt prüfen]   ← button re-enabled

✓ Integrität bestätigt         ← green, 14px/600, with checkmark text prefix
  SHA-256 stimmt überein.      ← 14px text muted
```

**Failure:**
```
[Integrität jetzt prüfen]   ← button re-enabled

✗ Integritätsfehler            ← red (#dc2626), 14px/600, with X text prefix
  SHA-256 weicht ab.           ← 14px text muted
  Datei möglicherweise verändert. Bitte Original-Bundle prüfen.
```

**Server error (hash endpoint unreachable):**
```
Prüfung fehlgeschlagen. Bitte erneut versuchen.   ← red error banner
```

Interaction:
1. User clicks "Integrität jetzt prüfen"
2. Alpine sends `POST /api/archive/:id/verify` (or `GET /api/archive/:id/verify` — planner picks)
3. Server re-hashes the file on disk and compares against stored `sha256` in `metadata.json`
4. Server returns `{ ok: true }` or `{ ok: false, reason: "hash_mismatch" }` or 500
5. Alpine renders result inline below button. No page reload.
6. Result persists until user navigates away or re-clicks the button (which resets to checking state)

## Interaction Contract

### List Page Navigation

1. Server renders `/archive` with full list of entries (chronological descending) as a `<table>`
2. Each `<tr>` has `onclick="location.href='/archive/{id}'"` (or wrapped in `<a>`) — entire row navigates to detail
3. Hover state applied via CSS `.table-row:hover` — no Alpine needed for this
4. "Neue Datei hochladen" button navigates to `/` (upload form)
5. No client-side pagination in v1 — server renders all entries. If > 200 entries, planner may add simple server-side offset pagination; UI contract for pagination: previous/next links at bottom of table, 14px text muted

### Detail Page Load

1. Server renders `/archive/:id` with all metadata fields pre-populated as HTML
2. No JavaScript required to display metadata — it is server-rendered
3. Alpine.js manages only: integrity verify button state + copy-to-clipboard interactions
4. Back link (`← Zurück zum Archiv`) is a plain `<a href="/archive">`

### Integrity Verify Flow

1. User clicks "Integrität jetzt prüfen"
2. Alpine sets state `checking: true` → button shows "Integrität wird geprüft …", disabled
3. `fetch('/api/archive/{id}/verify', { method: 'POST' })` issued
4. On resolve:
   - `{ ok: true }` → state `result: 'ok'`; renders success block
   - `{ ok: false }` → state `result: 'fail'`; renders failure block
   - Network error or non-200 → state `result: 'error'`; renders error banner
5. Button re-enabled after result. Result block persists until button clicked again (which resets `result: null`, `checking: false`).

### Copy-to-Clipboard (Archive ID, SHA-256)

Reuses Phase 2 pattern:
- `navigator.clipboard.writeText(value)`
- Button label changes to "Kopiert!" for 2 seconds via Alpine `setTimeout`, then reverts to "Kopieren"
- Alpine `x-data` reactive state on the parent card

## Accessibility Baseline

All Phase 2 requirements carry over. Phase 3 additions:

- Table uses `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`, `<td>` semantic elements — no `<div>` table simulation
- Clickable table rows: each row contains a visually hidden `<a>` or the `onclick` is keyboard-accessible with `tabindex="0"` and `role="row"` keyboard Enter activation, OR each row's filename cell contains an explicit `<a>` link and the row click is enhancement-only
- TSA status badges: color is never the sole carrier — text label always present
- Integrity verify result: screen reader announcement via `aria-live="polite"` on the result container, so Alpine-injected result text is announced without page reload
- All interactive elements retain `outline: 2px solid #16a34a; outline-offset: 2px` focus ring (inherited from Phase 2 global CSS)
- Back link: standard `<a>` — no special treatment needed

## Implementation Notes for Executor

- New CSS classes for Phase 3 (table, TSA badges, verify result states) are appended to the existing `src/static/style.css` — do not create a second stylesheet
- The integrity verify endpoint `POST /api/archive/:id/verify` must be implemented alongside the browser routes — it reads the file from the filesystem, computes SHA-256, and compares to `metadata.json`. Returns `{ ok: boolean }` JSON. Auth: session cookie required (same middleware as browser routes).
- File size display: format bytes using `Intl.NumberFormat` in Node.js at render time — do not expose raw bytes to the frontend template string; the server renders the human-readable string
- MIME type displayed as-is from `metadata.json` (e.g. `application/pdf`) — no mapping to friendlier labels in v1
- TSA provider raw values expected from `metadata.json`: `"dfn"`, `"freetsa"`, `"local-fallback"`, potentially `"digicert"`. Badge renderer maps these: `"dfn"` → badge class `tsa-badge--ok`, label "DFN"; `"freetsa"` → `tsa-badge--ok`, label "FreeTSA"; `"local-fallback"` → `tsa-badge--local`, label "Lokal"; unknown or `tsa_status === "failed"` → `tsa-badge--failed`, label "Fehlgeschlagen"
- SHA-256 display truncation: show first 16 hex characters + "…" in the label. Full 64-char hex goes into clipboard. Render the full value as a `data-sha256` attribute on the copy button for Alpine to read.
- The "Neue Datei hochladen" button in the list page header navigates to `/` — the existing upload form from Phase 2
