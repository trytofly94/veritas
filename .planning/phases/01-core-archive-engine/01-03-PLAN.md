<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host kernel → container | Container should drop capabilities, run non-root, read-only rootfs optional |
| Container → host bind mount | Container writes to `/data`; mapped to `./data` on host; uid/gid permissions matter |
| External (LAN) → container port 3000 | Phase 1 has no auth, so port 3000 must NOT be published outside the LAN until Phase 2 layers API-key middleware |
| Image build → npm registry | Supply chain risk; mitigated by `npm ci` + committed lockfile |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of privilege | Container runs as root | mitigate | Dockerfile creates user `app` (uid 10001), drops to USER app before CMD. Verified via `docker inspect --format '{{.Config.User}}'` in acceptance criteria. |
| T-03-02 | Information disclosure | Image accidentally bakes in test data or .env | mitigate | .dockerignore excludes tests/, data/, .env*, node_modules. `docker history auto-archive:phase1` reviewed manually during Task 1. |
| T-03-03 | Tampering | Bundle files on host owned by container uid → host user cannot read | mitigate | Documented in README; user can `chown -R 99:100 ./data` (Unraid nobody:users) if needed. Phase 1 leaves uid 10001; Phase 2 can revisit if it causes friction. |
| T-03-04 | DoS | Unbounded /data volume growth | accept (Phase 1) | No quota in Phase 1; user owns disk capacity. Documented in README. Phase 2+ may add retention policies. |
| T-03-05 | Information disclosure | Port 3000 reachable from LAN without auth | mitigate | docker-compose.yml binds `3000:3000` (all interfaces) but README explicitly warns: "Phase 1 has no auth; DO NOT expose port 3000 to the internet. Phase 2 introduces API-key middleware before publishing via Cloudflare Tunnel." STATE.md blocker captures this. |
| T-03-06 | Tampering | Outbound TSA traffic blocked by Unraid network policy → silent fallback to DigiCert without operator noticing | mitigate | The Unraid checkpoint (Task 2) explicitly reads tsa_provider from the first real submission and records it. If DFN isn't reachable, the operator sees it immediately and decides whether to fix Unraid networking or accept FreeTSA primary. |
| T-03-07 | Supply chain | Compromised npm dependency | accept (Phase 1) | `npm ci` against committed lockfile is the baseline mitigation; Dependabot/Renovate considered v2. |
</threat_model>
